# Become. — Master Website Build Prompt

You are a world-class creative director, product designer, interaction designer, brand strategist, and senior frontend engineer.

Your task is to **design and build the complete official website for `Become.`** inside the existing project.

Do not merely create a plan, wireframe, or design description. Inspect the repository, understand the existing setup, use the available assets, and implement the production-quality website.

---

Become. is a modern technology company that helps businesses transform through:

- Software products

## 4. Brand System

### Core colors

Use a restrained palette:

- Warm white or clean white
- Near black
- Soft neutral greys
- One signature orange/coral accent inspired by the Become. logo

The accent should feel premium rather than loud.

Avoid:

- Rainbow gradients
- Neon blue interfaces
- Excessive purple
- Multiple competing accent colors
- Large areas of oversaturated orange
- Random color changes between sections

Subtle warm gradients, glows, reflections, atmospheric light, and transparent surfaces are allowed when they support depth.

### Typography

Typography should carry much of the visual identity.

Use:

- Large editorial headlines
- Dramatic scale changes
- Tight, intentional line breaks
- Minimal body copy
- Strong contrast between display and utility text
- Precise letter spacing
- Generous whitespace

Choose a premium font strategy using `next/font` or existing project fonts. A clean grotesk or neo-grotesk should lead the system. A secondary editorial treatment may be introduced only if it strengthens the brand.

Avoid oversized text everywhere. Create rhythm through contrast.

### Shapes and surfaces

Use:

- Large clean surfaces
- Sophisticated grids
- Rounded corners with a consistent radius system
- Subtle glass only where appropriate
- Fine borders
- Soft shadows
- Layered depth
- Carefully controlled blur
- Large media containers
- Architectural spacing

Do not make every section a rounded card.

## 5. Experience and Motion

The website should feel alive, physical, and responsive.

Use Framer Motion as the primary animation system. Use GSAP only where it materially improves a complex sequence. Use Lenis for polished smooth scrolling if it remains accessible and performant.

Possible motion language:

- Text mask reveals
- Blur-to-sharp transitions
- Elegant opacity and scale changes
- Character or word morphing
- Layered parallax
- Image and video reveals
- Scroll-linked composition changes
- Hover elevation
- Magnetic buttons on pointer devices
- Animated borders
- Direction-aware hover states
- Cursor-responsive depth
- Slow ambient movement
- Sticky storytelling
- Seamless section transitions

Rules:

- Every animation must have a purpose.
- Motion should communicate transformation.
- Avoid generic fade-up animation on every element.
- Avoid excessive bouncing, spinning, or floating.
- Avoid a simple typewriter effect.
- Respect `prefers-reduced-motion`.
- Keep animation smooth on mid-range mobile devices.
- Do not sacrifice usability or performance for spectacle.
- Ensure the experience still looks polished before JavaScript animations complete.

Create one coherent motion system rather than unrelated effects.

## 11. Responsive Design

The mobile experience must be intentionally designed, not merely compressed.

For mobile:

- Preserve the brand impact of the hero
- Simplify complex scroll sequences gracefully
- Replace hover-only interactions
- Keep typography dramatic but readable
- Avoid overly tall empty sections
- Maintain clear CTA access
- Ensure navigation feels native and polished
- Reduce GPU-heavy effects
- Protect battery and scrolling performance
- Prevent clipped words and overflow

For tablet and desktop:

- Use whitespace and scale intelligently
- Create immersive but controlled compositions
- Keep line lengths refined
- Take advantage of pointer interactions without making them necessary

---

## 12. Performance Rules

Aim for a premium experience that remains fast.

- Avoid massive animation bundles
- Dynamically import heavy interactive sections when useful
- Prefer CSS and Framer Motion for common motion
- Use GSAP only for sequences that genuinely need it
- Pause off-screen video and expensive animation
- Avoid dozens of simultaneous blur filters
- Use transform and opacity for smooth animation
- Optimize fonts
- Preload only critical resources
- Use responsive image sizes
- Keep placeholders lightweight
- Prevent unnecessary rerenders
- Test the page at common breakpoints

---

## 13. Accessibility Rules

Accessibility is part of premium quality.

- Use semantic landmarks
- Provide meaningful labels
- Add alt text where content is meaningful
- Mark decorative media appropriately
- Ensure all controls are keyboard accessible
- Avoid cursor-only information
- Ensure animated words remain understandable to assistive technology
- Respect reduced motion
- Do not trap focus
- Make mobile menus accessible
- Maintain readable contrast in glass and overlay sections
- Keep touch targets appropriately sized

---

## 14. Non-Negotiable Design Safeguards

Do not build:

- A generic navbar + hero + card grid + testimonials + CTA template
- Repeated identical cards for every section
- A page filled with gradient blobs
- A dark page with neon blue borders
- A design dependent on icon libraries
- A layout that looks auto-generated
- A page where every heading animates identically
- A page with excessive glassmorphism
- A page that hides weak composition behind motion
- A site that introduces Become. as an agency
- A site that prioritizes technology logos over business transformation
- A site with generic filler copy
- A visual clone of Apple, Linear, Stripe, Vercel, Framer, or any reference brand

The design must have a strong art-directed rhythm and at least a few truly memorable moments.

## 15. Implementation Workflow

Work autonomously.

1. Inspect the repository, dependencies, routes, styles, and assets.
2. Preserve useful existing work.
3. Establish the design tokens and typography system.
4. Define the page architecture and content model.
5. Build the global layout and navigation.
6. Implement the hero and core transformation experience first.
7. Build each major section with reusable components.
8. Add motion with performance and accessibility safeguards.
9. Complete responsive behavior.
10. Add metadata and technical polish.
11. Run linting, type checks, and available tests.
12. Fix errors and warnings.
13. Review the final page visually and improve anything that feels generic, crowded, inconsistent, or unfinished.

Do not stop after scaffolding.

Do not leave major sections as TODO comments.

Do not return only code snippets when you can edit the project directly.

Before considering the work complete, verify:

- Does the first screen feel premium within one second?
- Is the central idea of transformation immediately clear?
- Does the brand name Become. carry the experience?
- Does the site avoid looking like an agency template?
- Is the typography strong enough without decoration?
- Are the sections visually distinct but part of one system?
- Is the motion purposeful?
- Are the AI and product sections substantial?
- Are placeholders elegant and replaceable?
- Is the mobile experience genuinely designed?
- Is the page accessible?
- Is the code maintainable?
- Is performance reasonable?
- Does the final CTA feel earned?
- Would a visitor believe this company can build serious products, AI, and digital systems?
- Does the website make someone think: “This company builds the future”?

If any answer is weak, improve the implementation before finishing.
